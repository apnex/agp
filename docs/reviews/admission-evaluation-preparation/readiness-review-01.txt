BLOCKING FINDING: MIXED-DECISION CONTRADICTION

PR-01. `admission-scoring-policy.mjs:30` requires every material unresolved
conflict to have aggregate `DECISION=withheld`; line 79 enforces that rule.
Line 68 simultaneously requires `DECISION=wrong` when `ISSUE=wrong-decision`,
and line 70 requires score 0. A question has multiple numbered decisions:
one can be wrong while a different one is withheld due to material conflict.
The correct aggregate score remains 0, but neither aggregate decision value can
satisfy the supplied contract. This is not a disputed semantic entailment or
mere inability to infer truth from tags; the declared fields are inconsistent.

Independent pure check, with `REQUIRED=R1,R2`, score 0, complete coverage,
partial support, `HEDGE=yes`, and `ISSUE=wrong-decision,support,conflict`:

- With `DECISION=wrong`, the checker returns exactly
  `unresolved conflict must withhold a decision`.
- Changing only the aggregate value to `DECISION=withheld` returns exactly
  `wrong-decision issue and decision tag disagree`.
- Both checks return their original score and reason unchanged.

The full reasons/results are retained in `readiness-review-01-test-output.txt`.
The test's exit 0 confirms these observed false flags; it does not mean the
expected empty-issue result was obtained. No runtime failure was reproduced.

Consequence: legitimate mixed evidence triggers a spurious contradiction and
cannot be expressed without hiding one deficiency or violating the prompt.
The checker does not itself change a score or automatically invalidate a run,
but the design makes such findings stop promotion. This violates the promised
mechanical discrimination and G2; successful single-deficiency tests do not cure it.

Required prospective correction: make aggregate precedence compatible with the
existing rule that any wrong/unsafe required decision scores 0, while retaining
the other decision's conflict, affected IDs and explanation. Add an actual
unrelated mixed semantic case and ordinary checks that accept its valid zero
record, preserve the original fields, and still reject a nonzero/full-credit
version. Do not repair old votes or treat this report as approval of a particular
patch. Preserve this failed target and recheck the exact corrected artifact.
