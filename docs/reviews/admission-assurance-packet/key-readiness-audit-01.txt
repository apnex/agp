The D rubric requires **every numbered decision**, explicitly and completely. The G rubric likewise requires all numbered decisions for a two. Therefore an adjacent, correct design rule becomes a hidden requirement whenever it is present in the key but absent from the question.

- **Q19:** `admission-key.json:584`; `scenario.json:592`. The question asks the cleanup configuration/anchor, phase budgets and migration effect. The key additionally requires explicitly excluding `StopPolicy.drainTimeoutMs` and a new global stop deadline.

A static Q19 witness makes the problem concrete:

> Use resolved `timers.transportCloseTimeoutMs`, default 5000 ms, from terminal-cause commit. Migrating changes the close setting into a whole-teardown budget, leaving potentially less time for graceful close; update the FSM/configuration/types/schema/caller/migration descriptions together.

This answers the question and covers key clauses 1–3. Omitting the unasked StopPolicy exclusion nevertheless fails the literal D completeness rule and prevents G=2.
